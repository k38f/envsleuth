> 🕵️  Python 代码中环境变量的"侦探"。使用 AST 解析源代码,找出每一个 `os.getenv()` / `os.environ[]` / `os.environ.get()` 调用,并告诉你 `.env` 文件里少了什么。

再也不会上线到生产环境后才发现忘了配 `STRIPE_API_KEY`。


![envsleuth demo](demo.gif)


## 安装

```bash
pip install envsleuth
```

## 使用方法

```bash
# 扫描当前目录,对照 ./.env 检查
envsleuth scan

# 指定目录和 env 文件
envsleuth scan --path ./src --env .env.production

# CI 模式 —— 如果有变量缺失则以退出码 1 退出
envsleuth scan --strict

# 根据代码生成 .env.example
envsleuth generate

# 机器可读的输出
envsleuth scan --json
```

## 能识别什么

支持三种常见用法:

```python
import os

a = os.getenv("A")              # 必需 —— 必须在 .env 中
b = os.getenv("B", "fallback")  # 有默认值 —— 会警告但不强制要求
c = os.environ["C"]             # 必需(否则会抛出 KeyError)
d = os.environ.get("D")         # 必需
```

也能处理别名导入:

```python
from os import getenv, environ
import os as sys_os

a = getenv("A")
b = environ["B"]
c = sys_os.getenv("C")
```

变量名在运行时才能确定的情况(例如 `os.getenv(f"PREFIX_{x}")`)无法静态检查 —— 它们会在单独的警告区块中列出,这样你也能知道它们的存在。

## `envsleuth generate`

扫描代码并生成一个 `.env.example`,包含每个找到的变量、指向使用位置的注释,以及代码里给定的默认值(如果有):

```bash
$ envsleuth generate
Wrote 6 variables to .env.example

$ cat .env.example
# Generated by envsleuth — edit this file before committing.
# Each variable below is used somewhere in your code.

# used at src/app.py:8
AWS_SECRET=default-value

# used at src/app.py:3
DATABASE_URL=

# used at src/app.py:5
DEBUG=false
...
```

使用 `--force` 覆盖已有文件,使用 `--output path/to/file` 写入其他位置。

## `.envignore`

通过 glob 模式排除变量(每行一条):

```
# .envignore
TEST_*
LEGACY_*
DEBUG_TOOL
```

适用于那些来自 CI、Docker 或 shell 配置文件而非本地 `.env` 的变量。

## CI 用法

GitHub Actions:

```yaml
- name: Check env vars
  run: |
    pip install envsleuth
    envsleuth scan --env .env.example --strict
```

pre-commit:

```yaml
# .pre-commit-config.yaml
- repo: local
  hooks:
    - id: envsleuth
      name: envsleuth
      entry: envsleuth scan --strict
      language: system
      pass_filenames: false
```

## CLI 参考

### `envsleuth scan`

| 参数 | 说明 |
| --- | --- |
| `--path`, `-p` | 要扫描的目录或文件。默认: `.` |
| `--env` | `.env` 文件路径。默认: `./.env` |
| `--envignore` | `.envignore` 路径。默认: 若存在则使用 `./.envignore` |
| `--strict` | 若有变量缺失,以退出码 1 退出 |
| `--json` | JSON 输出,适用于 CI 流水线 |
| `--no-color` | 禁用 ANSI 颜色(也遵循 `NO_COLOR` 环境变量) |
| `--exclude DIR` | 额外要跳过的目录名。可重复使用 |
| `--ext .EXT` | 额外要扫描的文件扩展名(例如 `.pyi`)。可重复使用 |
| `--verbose`, `-v` | 显示每个变量的所有使用位置 |
| `--no-update-check` | 跳过每周一次的 PyPI 新版本检查 |

### `envsleuth generate`

| 参数 | 说明 |
| --- | --- |
| `--path`, `-p` | 要扫描的目录或文件。默认: `.` |
| `--output`, `-o` | 输出位置。默认: `./.env.example` |
| `--force`, `-f` | 覆盖已有输出文件 |
| `--no-color` | 禁用成功消息中的 ANSI 颜色 |
| `--exclude`, `--ext` | 与 `scan` 命令相同 |
| `--no-update-check` | 跳过每周一次的 PyPI 新版本检查 |

## 更新通知

envsleuth 每周最多检查一次 PyPI 上是否有新版本。当有新版本时,会在 stderr 输出一行提示:

```
ℹ  envsleuth 0.2.0 is available (you have 0.1.1). Run: pip install -U envsleuth
```

检查带有缓存,使用很短的超时,在任何错误情况下(离线、网络被屏蔽等)都保持静默。完全禁用:

```bash
# 单次命令
envsleuth scan --no-update-check

# 全局设置(整个 shell 会话)
export ENVSLEUTH_NO_UPDATE_CHECK=1
```

缓存位置:`~/.cache/envsleuth/last_check.json`(或 `$XDG_CACHE_HOME/envsleuth/...`)。

## 与其他工具对比

| | envsleuth | [dotenv-linter](https://github.com/dotenv-linter/dotenv-linter) | [python-decouple](https://github.com/HBNetwork/python-decouple) |
| --- | --- | --- | --- |
| 扫描**代码**中的环境变量调用 | ✅ | ❌ | ❌ |
| 检查 **.env 文件本身**的格式 | ❌ | ✅ | ❌ |
| 运行时配置读取与类型转换 | ❌ | ❌ | ✅ |
| 从代码生成 `.env.example` | ✅ | ❌ | ❌ |
| 语言 | Python | Rust | Python |

envsleuth 是这里唯一真正"读懂"你**源代码**的工具。其他工具要么单独检查 `.env` 文件,要么只在运行时读取环境变量。
